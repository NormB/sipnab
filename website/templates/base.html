{# Browser-level security policy. GitHub Pages cannot set response headers, so this meta CSP is the enforceable layer there; the full header set (incl. frame-ancestors/HSTS, which meta cannot carry) lives in static/_headers for hosts/proxies that honor it. 'wasm-unsafe-eval' + connect-src 'self' keep the /analyze/ WASM tool working. script-src still grants 'unsafe-inline' here, and that is a constraint rather than a preference. Production's real script-src is hash-pinned at the Cloudflare edge; a browser enforces every delivered policy INDEPENDENTLY and blocks anything either one rejects, so this tag cannot name the same hashes without carrying them — and it cannot, because the hashes are taken over rendered HTML and two of the inline scripts contain Tera expressions. Deleting 'unsafe-inline' from a policy that has no hashes does not harden the page, it blanks it: the nav toggle, the docs dropdown and search all stop working on every page, in production, because this policy would then reject the very scripts the edge policy allows. script-src-attr 'none' closes the half of that grant this repository can close unconditionally. It governs inline event-handler attributes only, so it does not touch the four legitimate inline script elements, and it makes an injected onerror=/onclick= payload inert even on a host with no edge policy in front of it — which is exactly the shape of XSS a lone 'unsafe-inline' would permit. The templates provably carry no handler attributes (no_inline_event_handlers_in_templates), so nothing legitimate is lost. Removing 'unsafe-inline' outright needs the inline scripts externalized to .js files first; see ops/cloudflare/README.md. #} {% block title %}{{ config.title }}{% endblock title %} {# og:type is per-page, not a constant.
