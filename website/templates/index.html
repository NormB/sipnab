Install and open your first capture

On macOS, brew install NormB/tap/sipnab replaces the first step.

1. Install sipnab

bash 
curl -fsSL https://sipnab.com/install.sh | sh

2. Download a sample capture

bash 
curl -fsSLO https://sipnab.com/demos/sample-call.pcap

3. Open it in the terminal UI

bash 
sipnab -I sample-call.pcap

4. Or print a report without the UI

bash 
sipnab -N -I sample-call.pcap --report

5. Capture live SIP traffic

bash 
sudo sipnab -d eth0

What you can do with it

Inspect

Ladder diagrams, auth collapse, retransmit folding, mark+delta timing — the whole call at a glance.

Diagnose

Per-stream jitter, loss, and MOS. One-way audio, NAT mismatch, post-dial delay — found, not guessed.

Export

PCAP-NG, JSON/NDJSON, Mermaid, Wireshark filters, fail2ban, WAV — pipe it anywhere. The full list is below.

Ask what a capture holds, then ask about one call in it. The first command lists every dialog: a phone registering, the PBX probing it with an OPTIONS, two subscriptions, and one call placed, answered and hung up.

The second command draws that call's ladder, with media beside signaling. So the 64.3% packet loss on one direction of the audio sits next to the transactions it belongs to. That loss arrived in three bursts rather than spread evenly, which sounds far worse to the person on the call.

The terminal UI, which is what sipnab -I capture.pcap opens. Browse SIP dialogs, select one, and drill into its call-flow ladder with the parsed message beside it. Open a different capture any time with O — no restart.

The detail pane of the terminal UI reads the parsed message beside the ladder. Cycle how SDP is shown with d, and toggle wrapping with w when a header runs wider than the pane.

Measuring a gap, in the terminal UI. Press m on any message to mark it, then move to another: the Δ badge shows the exact millisecond distance between the two, so “the 200 came back slowly” becomes a number.

Finding one call among thousands, in the terminal UI. Press / and the dialog list narrows as you type, matching method, From, To and Call-ID at once.

One conversation, two Call-IDs. A back-to-back user agent answers on one and dials out on another, so the two halves look like unrelated calls. In the terminal UI, x stitches the correlated legs into a single ladder you can read end to end.

The media side, in the terminal UI. Tab switches from dialogs to RTP streams. Selecting one opens its detail: SSRC, codec, jitter, loss and estimated MOS, with quality plotted over the life of the call.

No terminal UI at all. -N runs sipnab headless for a script or a pipeline: emit every dialog as JSON with --json, narrow to the calls that went wrong with --problems, or print a full call report with --report.

Check what sipnab supports

sipnab runs as one process you start and stop. It has no database, no web interface, no login and no service to keep running, and that is on purpose. If you need dashboards and months of history, use Homer, and let sipnab feed it over HEP.

Capability Details
Terminal UI and headless modeBrowse calls interactively, or run headless for scripts and pipelines.
RTP quality analysisJitter, packet loss and estimated MOS (ITU-T G.107 E-model) for every stream, plus RTCP XR (RFC 3611) reports.
VoIP diagnosisFinds one-way audio, NAT mismatches and slow call setup, with the SDP timeline behind each.
Relay statisticsAsks rtpengine or rtpproxy for its own counters over its read-only control port, and marks them relay_reported: the relay's claim, kept apart from what sipnab measured.
Filter DSL32 fields, 8 operators and boolean logic, with named aliases for common queries.
SecurityDetects scanners, toll fraud, leaked digest credentials and registration floods, and writes fail2ban output.
TLS/SRTP decryptionDecrypts TLS 1.2 and 1.3 with an SSLKEYLOGFILE, and verifies SRTP with the SDES keys from the SDP.
WASM pluginsLoads your own dialog detections as sandboxed WebAssembly (--plugin). Off by default, and only in builds with the plugins feature: the gnu and macOS builds carry it, the static musl builds do not.
eBPF TLS capture (root, same host)This does not break TLS. On a host where you already have root, kernel uprobes read the SIP plaintext inside OpenSSL or wolfSSL before it is encrypted, so no key, certificate or restart is involved. The bpf backend also recovers the peer addresses. It is in the released Linux gnu tarballs, .deb and .rpm, not the static musl builds, and needs a kernel with BTF. Read the security implications first.
Export formatsPCAP, PCAP-NG, TXT, JSON, NDJSON, CSV, HTML, Markdown, WAV audio, SIPp XML and RTP JSON.
HEP v2/v3Sends HEP v3 to Homer, and receives HEP v2 and v3 from Kamailio, OpenSIPS or Asterisk, so one sipnab reads every proxy with nothing installed on them.
REST APIQuery dialogs, streams and stats over HTTP.
Prometheus metricsCounters about sipnab itself: what it captured, what it lost and what it could not read.
MCP serverLets an AI agent such as Claude Code query captures over stdio or HTTP. 69 tools cover dialogs, RTP, diagnostics, and security findings. 57 are read-only, and the twelve that write stay off until you enable them on the server.
Browser analysisOpens a pcap in your browser with WebAssembly. Nothing is uploaded or installed.
Built in RustRust everywhere except the OS boundary: 101 unsafe blocks, all of them FFI, and the build rejects any block that does not state its own soundness argument. 10009 automated tests. Under 17 MB static binary.
